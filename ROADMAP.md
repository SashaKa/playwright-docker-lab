# Roadmap (учебный план)

Цель: за 3–4 недели получить проект, о котором можно честно рассказать на интервью SDET/AQA, и закрыть пункты Playwright (TS) и CI/CD из списка «для изучения».
Правило: каждую задачу закрываю отдельным коммитом или PR, чтобы история в GitHub показывала прогресс.

## Неделя 1. Основа Playwright
- [ ] 1. Запустить тесты локально и в `--ui`, прочитать отчёт и trace упавшего теста.
- [ ] 2. Записать сценарий через `npm run codegen`, переписать его на `getByRole` / `getByTestId`.
- [ ] 3. Вынести inventory, cart, checkout в page objects (`pages/`), переписать `checkout.spec.ts`.
- [ ] 4. Тесты сортировки товаров (name A→Z/Z→A, price low→high/high→low) — table-driven, как в `login.spec.ts`.
- [ ] 5. Негативные тесты формы checkout (пустые поля) — эквивалентные классы.

## Неделя 2. Структура фреймворка
- [ ] 6. Fixtures: `loggedInPage` через `test.extend`, убрать повторяющийся логин.
- [ ] 7. Авторизация один раз: `storageState` + setup-проект.
- [ ] 8. Тестовые данные в отдельном модуле (`test-data/`), пользователи saucedemo как константы.
- [ ] 9. Теги `@smoke` / `@regression` и запуск через `--grep`.

## Неделя 3. Docker и CI/CD
- [ ] 10. Собрать образ (`docker compose build`), прогнать тесты в контейнере, объяснить каждую строку Dockerfile.
- [ ] 11. Зелёный прогон в GitHub Actions; сломать тест специально → увидеть красный CI → скачать отчёт из artifacts.
- [ ] 12. Защита ветки `main`: merge только при зелёном CI, работа через PR.
- [ ] 13. Шардинг (`--shard=1/2`) в матрице и запуск по расписанию (`schedule`).

## Неделя 4. API и витрина
- [ ] 14. API-тесты через `request` на публичном API (например, reqres.in или jsonplaceholder): статусы, схема ответа, негативные кейсы.
- [ ] 15. Мок ответа 500 через `page.route` и проверка UI-заглушки (тема из подготовки к интервью).
- [ ] 16. Allure или опубликованный HTML-отчёт (GitHub Pages).
- [ ] 17. README: что покрыто, как запускать, бейдж CI. Ссылка на репозиторий — в резюме и LinkedIn.

## Что говорить на интервью, когда готово
«Собрала фреймворк на Playwright + TypeScript: Page Object, fixtures, storageState, table-driven тесты по эквивалентным классам, UI и API. Тесты гоняются в Docker на официальном образе с закреплённой версией и в GitHub Actions матрицей по браузерам с шардингом, отчёты в artifacts, merge блокируется при красном CI.»
Говорить только про пункты, которые реально сделаны.
